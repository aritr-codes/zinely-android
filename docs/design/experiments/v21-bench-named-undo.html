Named undo — the undo snack amendment (A26)

Step 3 of the 1.x plan (Brief 04 A3, gate 3). After an undo, the Bench's existing support-paper snack says what came back — and the page, when the undo takes you to another page. One snack, no button, spoken once. This page asks for two things: approve the recommended words (§A) and rule the four open decisions (§B). Base origin/main a6eb16b, branch design/step3-undo-snack.

Every phone below is the real v21-bench.html staged by its ?a26= review stages; each shows the lower half of the phone at 1:1. In the live prototype, delete, flip and duplicate really undo with their named line: select something, act, then press the snack’s Undo or the bar’s Undo. Undo after Add Art or Across fold shows the words but reverts nothing, as the frozen prototype already did; ink is not demonstrated live. The prototype undo is one level deep. Add ?d1=a or ?d1=b to try the duplicate options.

What stays exactly as frozen

  • The snack itself: pill, support-paper ground, ink border, .79rem type, the −0.6° tilt, 88px above the phone bottom (A8: 12px above a live context bar), the 180ms entrance, the 3200ms dwell. Nothing is restyled.
  • One slot. A new line replaces the last; there is never a second snack or a second speaker.
  • Undo is a snack, not a dialogue. An undo snack carries no button — no Undo, no Redo.
  • Forward snacks (“Removed · …”, “Duplicated”, “Flipped …”, “Placed on the page”) are unchanged and keep their Undo.

What changes: the three frozen post-undo lines — “Put back” after a delete (:810) and after a flip (:1068), and “Duplicate undone” (:2216) — become named lines, and every undo gets one. Today an undo after a placement, a spread or an ink also says “Put back”, which puts nothing back.

A · Recommended words — for approval

Two to four words. Paper words: the thing, then what happened to it on the way back. No coordinates, no command names, never the bare word “Undo”. The thing is Text, Photo, Art piece, or 3 things when one act held several.

The act that was undoneNamed from the command’s diffThe snack says

Rules that come with the table

  • Page clause. When the undo lands on another page, the Bench goes there, clears the selection, and the same line gains , page N: Photo put back, page 3. It replaces today’s hard-coded “Changed page N”. A comma, not “·”, so the spoken line is the seen line with no symbol for TalkBack to read or drop.
  • Toggles name the state that came back: undoing Copier-on says Copier taken off; undoing Copier-off says Copier put back. Flips likewise, per axis.
  • Words before style. One text edit that changed both the words and the style says Words put back.
  • Add Text is two undo steps. The Bench places an empty box, then your typing is a second step. So the first undo says Words taken off (the box stays, empty), and the next says Empty box taken off.
  • Replace on an Art piece also refits its box; the swap outranks the refit (Art piece swapped back).
  • Reframe always says Framing put back. D2 only decides whether a genuine Reset framing gets its own words.
  • Restacking: approving this table also rules the decision gate’s “restack direction” item. An adjacent restack swaps two ranks, so “forward” and “back” are the same diff; one direction-free line fits.
  • Nothing left to undo: no new snack.
  • Repeats: each undo is a new snack instance (keyed per step), so a second identical undo is meant to be spoken again. Whether TalkBack re-speaks it is checked on device, per Brief 04.
  • Not covered: adding or deleting a page. No Bench control does either today.
  • On freeze, VOICE.md’s undo confirmation (“Undone. You can redo it.”, :157) is superseded by this table and updated in the same change.
  • Weakest line, for your ear: Photo off the fold (undoing Across fold). Clearer but five words: Photo back on one page.

B · Open decisions — the owner rules these

Each table marks the option that appears most consistent with the rules already frozen, and says why. That is a reading of the record, not a choice.

Both acts are one PlaceCommand, so the diffs look the same. What the maker sees differs: after undoing a duplicate, an identical original is still on the page, 12pt away.

D2 · Undo after a genuine Reset framing

A Reframe that happens to end at the default look and a genuine Reset produce the same diff. Reframe says Framing put back either way (§A); this decides only whether a genuine Reset gets its own words. The rule holds in every option: a return to the default look is never called a reset just because it looks like one.

OptionExact wordsBehaviourImplicationsReading of the record
2a One line for bothFraming put back after eitherNo flag. Always true: the framing that came back is the one before, whatever made it. Never says “reset”. Brief 04 leans this way; it needs no command change and cannot misname.
2b Name a genuine ResetReset taken back after the Reset framing action; Framing put back after any Reframe A defaulted flag on EditImageCommand, set only at the Reset framing action (EditorReducer.kt:192). Names the act the maker chose. But the Reset framing action is reached today only through the TalkBack custom action (EditorA11y.kt:119); the visible Reset inside Reframe only changes the draft, and Done commits it as a Reframe, so it says “Framing put back” — still true. In practice 2b’s extra words are heard only by TalkBack makers. Allowed by the rule, since only a real Reset uses the word.

Not offered: calling an undo “reset” whenever the framing it removed was the default look. That is the inference the brief forbids.

D3 · What Redo shows and says

The frozen Bench draws Redo disabled and never specifies its feedback. The shipped app’s Redo works, and today it speaks only “Changed page N”, only when it jumps page.

D4 · One command that changed position, size and turn

Two real cases make several properties change at once, so the rule has to pick one word:

  • Every handle resize moves the centre. It holds the opposite corner still (TransformMath.bakeHandleResize), so position always changes with size. “Moved back” after a resize would name a side effect.
  • Every two-finger gesture changes all three. Zoom and rotation accumulate from the first motion with no snap (EditorGestures.kt:171-199), so a two-finger move also changes size and angle slightly. A strict “size before position” rule then says “resized back” after a move. A one-finger drag is clean.

Whatever the order, several selected things use the same order, taken over all of them.

OptionExact wordsBehaviourImplicationsReading of the record
4a Size first, strictA pinch that grew and turned: Photo resized back. A two-finger move: Photo resized back size → turn → position; any change at all counts Right after a resize and a pinch. Wrong after a two-finger move, and nothing in the words warns the maker. VOICE names the pinch a resize (“Drag to move · pinch to resize”), but this misnames a move.
4b Turn first, strictA pinch that grew and turned: Photo turned back. A two-finger move: Photo turned back turn → size → position; any change at all counts Names the rarer, deliberate change 🟨, but any stray angle turns a resize or a move into “turned”. Nothing frozen supports it over 4a.
4c Size first, ignoring slipsA pinch that grew and turned: Photo resized back. A two-finger move: Photo moved back size → turn → position, but a size or turn change counts only past a small fixed tolerance (e.g. 2% of size, 2°). Named constants, so it stays deterministic and testable Names what the hand meant in all three cases. Costs two constants, and a deliberate 1° nudge from a two-finger gesture reads as a move. Brief 04: “an undo name is never wrong” (:120-121). The tolerance values are yours to set or delegate.

Not offered: Photo back in place when several changed. It never names the wrong property but says less, and Art piece back in place is five words. Nor position first: every handle resize would say “moved back”.

F · Page-changing undo

The photo was deleted on page 3; the maker went to page 6 and pressed Undo. The Bench returns to page 3 and says so in the same line — no second snack, no separate announcement.

G · Repeated identical undo

Two undos that name the same thing are two snack instances: the text node is replaced and the frozen entrance restarts from hidden (live prototype: undo twice), so the second is meant to be spoken again — whether TalkBack re-speaks it is checked on device.
