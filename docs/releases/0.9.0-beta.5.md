# Zinely 0.9.0-beta.5 - tester package

## Zinely - steadier editing and saving

This maintenance update makes editing and saving more dependable. On Android 7–9, Save PDF now asks for
storage access instead of failing. About opens with a short note from the makers, and the font licences
sit one tap away behind **Licences & credits**. Reframe opens large photos more smoothly, and several
editing fixes land. The full list is in the [changelog](../../CHANGELOG.md#090-beta5--2026-09-23--steadier-editing-and-saving).
Saved zines, backups and the document format are unchanged.

## Before installing

This APK uses the same Zinely release key as beta.1 through beta.4-r3, so Android can update an existing
release-signed beta without deleting its data. **Do not uninstall the existing app.** Make a fresh backup
from **Backups** before any beta update.

1. Download `zinely-0.9.0-beta.5-release.apk` to the phone.
2. Tap it, allow that file-opening app to install unknown apps if Android asks, then return to the installer.
3. Choose **Update** / **Install**, then open Zinely normally.

### If you have Zinely 0.8.0 or older

Those builds use a different signing key, so Android cannot update them to this beta. Preserve anything
you care about **before** uninstalling the old app: in 0.8.0 use **Preview › → Print setup → Save PDF**;
in 0.6.0-alpha.1, which has no save action, share the zine somewhere durable. Only then uninstall the old
build and install this APK. Uninstalling the old build deletes its private library.

Zinely requires Android 7.0 or newer. It has no account, analytics, cloud sync, or network permission.

## What to verify

1. Existing zines and backups remain reachable after updating.
2. **About** opens with the makers' note; **Licences & credits** lists three typefaces, and each opens its
   licence. Back returns one level at a time.
3. On **Android 7, 8 or 9**: the first **Save PDF** asks for storage. Allowing saves the PDF once; declining
   shows "Couldn’t make the PDF", and **Try again** asks again. **Share** never asks. *(Not yet verified on
   a real Android 7–9 phone. If you have one, this is the most useful thing you can check.)*
4. Reframe on a large photo opens without stutter.
5. Add, Replace, Flip, Across fold, Duplicate, Delete, Undo, Read, Save PDF, Share and Print & fold remain
   unchanged.

## Known limitations

The authoritative list is the changelog's
[Known limitations](../../CHANGELOG.md#090-beta5--2026-09-23--steadier-editing-and-saving). In short:
transparent pictures show a white box on the cream page (exports print correctly); on Android 7–9, choosing
"don't ask again" leaves Save PDF on its error until storage is allowed in Settings; replaced photo assets
are retained; there is no font choice; printing happens in another app. Google Play distribution is not
available; this beta is distributed directly through GitHub as an APK.

## Verification

### Automated (release tree `1adfba4`)

- 2,203 unit tests across all twelve modules, 0 failures, including `SavePdfPermissionHostTest` (7 tests:
  ask first, grant saves once, deny shows the error without re-asking, Try again re-asks, no re-ask after a
  grant, never on Android 10+, never for Share).
- Golden verification (`verifyRoborazziDebug --rerun-tasks`, three modules) passed; no golden changed or was
  re-recorded.
- CI run `35868719437` on PR #74 green. An earlier run on `61a28fb` failed once on an unrelated, timing-
  sensitive test (`backgrounding Home commits a pending delete…`); no production code differs between the two.
- `:app:assembleRelease` via [RELEASING §2](../RELEASING.md). A second assembly re-ran only
  `lintVitalRelease`; packaging and signing were `UP-TO-DATE`. The `dist/` APK was verified with `aapt2` and
  `apksigner` (version, certificate, permission cap above).

### On device - Samsung SM-A176B, Android 16 (API 36), build `A176BXXS7CZH3`, 2026-09-24

**Install over r3.** The phone held r3 (`versionCode 9`), byte-identical to the published r3 APK
(`35220423…`). `adb install -r` - no uninstall - was accepted. `firstInstallTime` stayed
`2026-08-31 18:19:22`; the app cold-launched in 335 ms. The shelf and the existing zine's editor view were
**pixel-identical** to the same screens captured on r3 before the update.

**Pass 1 - developer verification** (dark and light theme; text 1.0× and 1.8×):

- About → Licences & credits → licence → system Back unwinds one level at a time to the shelf. Back controls
  are named `Back to My Shelf`, `Back to About Zinely`, `Back to Licences & credits`; the three rows are
  buttons named `<family>, Read font licence`; every control measured ≥ 48 dp; the full SIL OFL text loads
  locally; the version reads `0.9.0-beta.5`. At 1.8× in light theme nothing clips and every control stays
  reachable.
- Save PDF (Android 16): no permission prompt; exactly one new `Download/zine.pdf` (2,541,151 bytes,
  `is_pending=0`), a valid PDF with one A4-landscape sheet. Share opened the system chooser with one PDF and
  no prompt.
- Editor: Add photo, Reframe (a 4096 × 3072 photo - no skipped frames, ANR or OOM logged), Replace, Flip,
  Across fold, Duplicate (+ its Undo), Delete (+ Undo), Undo across pages (Undo from page 1 jumped to page 2,
  reversed the flip, and left nothing selected), Proof page turning, and the fold guide all worked. Flipping
  one half of a spread applied to that half only, and the Proof showed the same thing as the Bench.
- The Backups sheet opened (Back up / Restore); no backup was made or restored. Nothing was printed on
  paper; the fold guide was opened on screen only.
- A transparent PNG came in on white - the white box on cream described in Known limitations.
- The crash buffer stayed empty throughout.

**Agent first-time reading** (the owner's own Pass 2 is still owed). About reads warmly and Licences & credits is easy to find; the Save PDF
confirmation says where the file went and how to print it. Observations, none new in beta.5:

- A new zine is also called "My zine", so two shelf cards - and their `Actions for My zine` buttons - can read
  identically, which is hardest on a TalkBack user.
- Share names the file with a raw timestamp (`zine-1790247267050.pdf`), which is what the recipient sees.
- The licence's dashed divider lines wrap at 1.8× text.

**TalkBack** (Samsung TalkBack 16.2.00.13) - *structural only*. On this phone `adb` input bypasses TalkBack's
touch exploration, so swipe gestures could not be driven and speech cannot be captured; a human listen is
still owed. What was checked: every beta.5 control has a name and role in the platform tree, and TalkBack's
focus position on entering and leaving each screen was read from screenshots. Findings:

- **TalkBack focus does not follow the frozen focus rules** ([COLOPHON-FREEZE](../design/COLOPHON-FREEZE.md#accessibility-semantics)):
  entering About, credits or a licence focuses the Back control, not the heading; returning from a licence
  lands on Back, from credits on the maker's note, and from About on the shelf title - not on the invoking
  row or dock action. Everything stays reachable. *Screens were navigated by tap, not TalkBack double-tap.*
- The default-paper choice exposes its checked state on a row `View` and the `RadioButton` role on a
  separate child node (the [ADR-059](../DECISIONS.md#adr-059) pattern); how it sounds needs the listen.
- The "Start a zine" sheet's dimmed backdrop is an unlabelled clickable node, and TalkBack lands on it when
  the sheet opens. A hardware-keyboard Tab also reaches the shelf card behind the sheet.
