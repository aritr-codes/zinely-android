# Design-token enrolment list  (conformance item CI-27, milestone C1)
# =====================================================================
#
# THE DEFINED TERM.  A package is "enrolled" when its fully-qualified Kotlin
# package name appears on a non-comment line in this file.  The token-discipline
# check (feature/editor/src/test/.../TokenDisciplineTest.kt) scans the production
# (src/main) sources of any enrolled package.  "Enrolled" is therefore a
# committed fact in this file, not a judgement about what has been migrated.
#   -- roadmap V1-IMPLEMENTATION-ROADMAP.md Section 10.2 / inventory CI-27.
#
# WHAT THE GATE CHECKS.  Traceability, not literal absence.  OD-29 (2026-08-09,
# disposition (b)) ruled:  "Token discipline for a V2 surface means every value is
# traceable to the frozen V2 source -- not that no literal appears."  A raw
# .dp / .sp / Color( / RoundedCornerShape( in an enrolled package is therefore
# COMPLIANT when it names where its value came from, and NON-COMPLIANT when it
# does not.  A value names its source with a provenance marker, on the literal's
# own line or in the comment block directly above it, in one of two forms:
#
#     v2-bench.html:351   a frozen address -- the trilogy declares or writes the
#     v2-proof.html:155   value at that line
#     v2-library.html:101
#
#     ADR-074  OD-45  D-007   a governed reference -- an accepted ADR or owner
#                             ruling that governs the value
#
# "approved" / "legacy" / "intentional" are not markers:  they name no source.
# A literal the mechanism cannot classify FAILS -- OD-29 forbids a silent pass.
# This is what lets D-006 (no V2 radius scale) and D-007 (spacing stays per
# component, "exactly as frozen") coexist with enrolment:  a value with nowhere
# to move to is compliant where it stands, once it says where it came from.
# There is no allowlist and no per-package exemption.
#
# ENROLMENT <-> MIGRATION COUPLING (mandatory).  A package joins this list in the
# SAME commit that migrates it onto the V2 design surface -- ZinelyV2Colors,
# ZinelyV2Typography, ZinelyV2Motion, ZinelyV2Shadow, ZinelyV2Dimens -- which is
# ADR-080 Decision 2's requirement in terms:  "Each of Phases B, C and D re-skins
# its surface onto V2 tokens and enrols that package in token-enrolment.txt in the
# same commit."  Enrolling a package that still holds an UNTRACEABLE value will
# (correctly) FAIL the build -- that failure is the whole point of the gate.  Do
# not add a package here "in advance".
#
#   SUPERSEDED WORDING, kept for the record (repaired by D0, ADR-098 row 0.6, on
#   the OD-29 ruling of 2026-08-09).  This clause used to read:
#
#     "...migrates it off raw literals and onto the design tokens (:core:ui
#      spacing/radius/colour, ZinelyColors, Type.kt).  Enrolling a package that
#      still contains any of the four literal forms will (correctly) FAIL..."
#
#   It named V1's migration targets and V1's test -- "off raw literals" -- and so
#   described a migration Phase D is not performing.  Both halves were wrong for
#   V2:  the destination is the ZinelyV2* surface, not ZinelyColors/Type.kt; and
#   the bar is traceability, not literal absence (see WHAT THE GATE CHECKS below).
#
# GRANULARITY.  Matching is by EXACT package name.  Sub-packages are NOT pulled
# in transitively: enrolling  com.aritr.zinely.ui  does not enrol
# com.aritr.zinely.ui.components -- each package enrols on its own line, in the
# commit that migrates it.  (This is why the palette itself, which lives in
# com.aritr.zinely.ui.theme / ZinelyColors.kt with 34 legitimate Color()
# literals, is never enrolled: the check is scoped by enrolment, not by file.)
#
# FORMAT.  One fully-qualified package name per line.  Blank lines and lines
# beginning with '#' are ignored.
#
